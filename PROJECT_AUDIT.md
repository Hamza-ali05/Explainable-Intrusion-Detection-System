## Project Overview

### What this project is

An end-to-end machine learning pipeline that:

1. Ingests raw IDS CSV datasets from `data/raw/`
2. Projects them onto a shared feature schema and maps labels to an 8-class threat taxonomy
3. Cleans, splits (70/15/15 stratified), preprocesses, and optionally balances training data (SMOTE)
4. Trains three tree models: Decision Tree, Random Forest, XGBoost
5. Evaluates on a held-out test set and generates a model card
6. Produces global and local SHAP/LIME explanations plus explanation-quality metrics (fidelity, stability, comprehensibility)
7. Serves results through:
   - **CLI:** `python -m src.pipeline <step>`
   - **Streamlit UI:** `ui/app.py` (port 8501)
   - **FastAPI REST API:** `api/main.py` (port 8000)
   - **React dashboard:** `frontend/` (port 3000, proxies `/api` → 8000)

### Technology stack

| Layer | Technology |
| --- | --- |
| Language | Python 3.10+ (implicit), JavaScript (React 18) |
| ML | scikit-learn, XGBoost, imbalanced-learn (SMOTE), SHAP, LIME |
| Data | pandas, pyarrow/parquet, joblib |
| API | FastAPI 1.x, Uvicorn, Pydantic, python-multipart |
| Legacy UI | Streamlit |
| Modern UI | React 18, Vite 6, Tailwind CSS 3, Axios, Recharts, react-markdown, react-router-dom 6 |
| Testing | pytest |
| Storage | **No SQL/NoSQL database** — file-based parquet, JSON, CSV, joblib, PNG |

### Threat taxonomy (8 classes)

Defined in `src/core.py` → `Config.THREAT_CLASSES`:

`BENIGN`, `DDoS`, `DoS`, `PortScan`, `BruteForce`, `WebAttack`, `Infiltration`, `Botnet`

`RANDOM_SEED = 42`, `MODEL_NAMES = ["decision_tree", "random_forest", "xgboost"]`

## Database Schema

**There is no relational or document database.** All persistence is file-based. Below are the logical schemas.

### 1. Shared integrated schema (`data/interim/integrated.parquet`)

After `integrate`, each row represents one network flow projected from any supported corpus:

| Column | Type | Required | Description |
| --- | --- | --- | --- |
| `duration` | float64 | yes | Flow duration (seconds) |
| `src_bytes` | float64 | yes | Source bytes |
| `dst_bytes` | float64 | yes | Destination bytes |
| `src_packets` | float64 | yes | Forward/source packet count |
| `dst_packets` | float64 | yes | Backward/destination packet count |
| `protocol` | string | yes | Protocol identifier |
| `service` | string | yes | Service name |
| `label` | string | yes | Raw source label |
| `threat_class` | string | yes | Mapped taxonomy label (one of 8 classes) |
| `source_file` | string | yes | Originating raw filename |
| `dataset_source` | string | yes | `cicids_csv`, `unsw_nb15_csv`, or `kddcup_csv` |

After `clean` + feature engineering, the cleaned frame retains ~78 CICIDS-style numeric features plus metadata (2.5M rows per EDA).

### 2. Split indices (`data/processed/splits.json`)

| Field | Type | Description |
| --- | --- | --- |
| `random_seed` | int | Always 42 |
| `target_column` | string | `"threat_class"` |
| `train` | int[] | Row indices for training (70%) |
| `val` | int[] | Row indices for validation (15%) |
| `test` | int[] | Row indices for test (15%) |
| `n_rows` | int | Total rows in cleaned/unscaled frame |

**Constraints:** Indices must be disjoint (enforced by `leakage_check()` in `src/model.py`).

### 3. Preprocess bundle (`artifacts/preprocess/preprocess_bundle.joblib`)

Python dict loaded at inference:

| Key | Type | Description |
| --- | --- | --- |
| `numeric_cols` | list[str] | Numeric feature column names |
| `categorical_cols` | list[str] | Categorical column names |
| `low_card_ohe` | list[str] | Columns one-hot encoded (cardinality ≤ 15) |
| `high_card_freq` | list[str] | Columns frequency-encoded (cardinality ≤ 20) |
| `one_hot` | OneHotEncoder | Fitted on train only |
| `freq_encoder` | FrequencyEncoder | Custom sklearn-compatible encoder |
| `scaler` | MinMaxScaler | Fitted on train only |
| `feature_names` | list[str] | Final model input column order |
| `train_fit_indices_hash` | string | SHA-256 of train index list |

### 4. Checkpoint marker schema (`checkpoints/<step>.done`)

| Field | Type | Description |
| --- | --- | --- |
| `step_name` | string | Pipeline step name |
| `input_hash` | string | SHA-256 of input file metadata + params |
| `output_paths` | string[] | Absolute paths to generated files |
| `params` | object | Step parameters used for hashing |
| `timestamp` | string | ISO 8601 UTC |

Per-model train markers: `checkpoints/train_<model>.done` with same structure, `step_name` like `train_xgboost`.

### 5. Evaluation metrics schema (`reports/evaluate/<model>/metrics.json`)

```json
{
  "accuracy": float,
  "precision": { "macro": float, "weighted": float, "per_class": { "<class>": float } },
  "recall": { "macro": float, "weighted": float, "per_class": { ... } },
  "f1": { "macro": float, "weighted": float, "per_class": { ... } },
  "mcc": float,
  "cohen_kappa": float,
  "roc_auc_ovr": float | null,
  "pr_auc": float
}
```

### 6. Local XAI instance schema (`reports/xai/local/selected_instances.json`)

| Field | Type | Description |
| --- | --- | --- |
| `generated` | string | ISO timestamp |
| `reference_model` | string | `"xgboost"` |
| `selection.per_class` | object | Per-class correct/wrong availability counts and chosen instance IDs |
| `instances[]` | array | Each: `instance_id`, `position`, `true_label`, `predicted_label`, `kind` (`correct`/`wrong`) |

16 instances total: 1 correct + 1 wrong per threat class.

### 7. Prediction output schema (inference)

`predict_from_dataframe` returns original columns plus:

| Column | Type | Description |
| --- | --- | --- |
| `predicted_label` | string | Model prediction |
| `predicted_proba_<class>` | float | Per-class probability (if model supports predict_proba) |
| `confidence` | float | Max probability |

Audit copies written to `reports/predictions/<timestamp>.parquet`.

### Migrations and seeds

- **Migrations:** None — schema evolves only through pipeline re-runs and checkpoint invalidation.
- **Seed data:** `scripts/seed_example_flows.py` creates `data/manual/example_flows.csv` (3 rows × 8 classes) from raw CICIDS for demo predictions. Not auto-run.

## Backend Architecture

### Framework and entry points

| Component | Entry | Command |
| --- | --- | --- |
| Pipeline CLI | `src/pipeline.py` | `python -m src.pipeline <command>` |
| FastAPI | `api/main.py` | `uvicorn api.main:app --reload --port 8000` |
| Streamlit | `ui/app.py` | `streamlit run ui/app.py` |
| Training plots | `src/train_plots.py` | `python -m src.train_plots` |

### Server bootstrap (FastAPI)

1. `ROOT` added to `sys.path`
2. `FastAPI(title="Cybersecurity XAI API", version="1.0.0")` instantiated
3. **CORS middleware:** `allow_origins=["http://localhost:3000"]`, all methods/headers, credentials enabled
4. Module-level `_pipeline_lock` (threading.Lock) and `_pipeline_running` flag for concurrent pipeline protection
5. No lifespan hooks, no dependency injection container, no auth middleware

### Authentication

**None.** All endpoints are public. No JWT, API keys, sessions, or OAuth. Anyone who can reach port 8000 can trigger pipeline runs and read all reports.

### Global middleware

- `CORSMiddleware` only (see above)

## Pipelines and Background Jobs

### ML pipeline (primary)

- **Trigger:** CLI, FastAPI POST `/api/pipeline/run`, Streamlit "Run" tab, or `run_app.bat` on first launch
- **Execution:** Synchronous in CLI; daemon background thread in FastAPI; background thread in Streamlit
- **Idempotency:** SHA-256 input hashing via `@checkpointed` decorator — re-runs skip completed steps
- **Reset:** `python -m src.pipeline reset --step <name>` deletes downstream markers (interactive confirm)
- **Timing:** Recorded in `reports/timing.json` per step
- **Reproducibility:** After `all`, writes `reports/env.json` + `requirements.lock.txt`

### CI/CD

**None.** No `.github/workflows/`, GitLab CI, Jenkins, or similar. No automated test runs on commit.

### Docker

**None.** No `Dockerfile`, `docker-compose.yml`, or container orchestration.

### Cron / scheduled jobs

**None.**

### Message queues / workers

**None.** Pipeline runs in-process (main thread or single background thread).

### Background processes in API

`_run_pipeline_background(step)` — one pipeline at a time, guarded by `_pipeline_lock`. Failures logged to `pipeline.log` and stderr; no callback to client except polling status/log endpoints.

### `run_app.bat` pipeline behaviour

On Windows, if `checkpoints/train.done` missing, automatically runs `python -m src.pipeline all` before starting Streamlit. Can take hours on first run with full CICIDS data.

| **Path traversal partially mitigated** | Low | `/api/reports/file` resolves path and checks `reports_root in candidate.parents` — good. |
